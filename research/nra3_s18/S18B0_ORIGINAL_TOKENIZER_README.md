# NRA3 S18b0 — оригинальный Calibri-токенизатор для новых 96 TRAIN (подготовка)

**Статус: RESEARCH ONLY / DRAFT / DO NOT MERGE / НЕ ЗАПУСКАТЬ В LIVE.**

Основание: независимый S17c (NEW24, уже использованный EVAL) дал **15,93% F1**, несмотря на **86,60% F1 на старых TRAIN72**. Диагностика S18a на 10 групповых разбиениях старых TRAIN72 подтвердила обобщение лишь около **45% F1**. Новые **S18**: 96 TRAIN предложений, 12 лексических семейств, 8 конструкций, 300 направленных связей AGENT/PATIENT/RECIPIENT/SOURCE. SHA исходного полного UD+role манифеста `abde63c34534d90e00a6ac61808d2453ce0cfc966c83d45377c1fb620999cca9` (успешный повторный CI `43904457245`).

## Выполняется сейчас

`locked_original43m_new96_token_alignment.py` задаёт контракт реального оригинального fast-tokenizer и его chat template. Только строка `TrainSentence.text` поступает в токенизатор; золотые POS, lemma, UD и semantic roles **не передаются в токенизатор или Calibri**. Соответствие 96 строк проверяется **по полному SHA и полному dataclass**, включая случай, когда изменили только роль и текстовый SHA не изменился. Каждому размеченному слову должно соответствовать не менее одного настоящего под-токена; единая BPE-часть не может пересекать границы слов. Требуется точное совпадение реальных input IDs и offset mapping; ошибочные, дублированные строки и повреждённая разметка отклоняются.

Unit-тесты пока используют искусственный симулятор токенизатора, чтобы проверить fail-closed контракт. **Это НЕ выполнение исходной 43M Calibri, НЕ capture hidden320 и НЕ обучение 2309 FP16 параметров.** Отсутствие ошибок unit-тестов не доказывает, что оригинальный BPE пройдёт все 96 предложений; это нужно проверять отдельным настоящим native CPU шагом.

## Следующий физический S18b (только после CI S18b0)

1. Открыть оригинальную **замороженную** Calibri43M+Green Tunnel / S194 CPU модель в том же физическом pipeline, что S17b, с подтверждением старых **616 J7** и неизменных FP16 SHA.
2. После исходных защищённых контрольных прогонов выполнить **96 реальных TRAIN prefill** с исходным fast-tokenizer и новым `align_s18_new96_train(..., expected_input_ids=ids)`, захватить только layer8 `hidden320`, физические CPU ids/offsets и SHA. Никаких gold-ролей внутри original43M; никаких ранее просмотренных EVAL (S17c/S15c/S12c).
3. Отдельно подать реальные исходные hidden320 в неизменные **43 оригинальные CB59 native-C** матрицы и неизменный S11 39-FP16 selector; затем и только затем обучать новый оплаченный параметрами вариант направленных связей, не изменяя S16b оригинал.
4. Оценивать на только TRAIN-internal с разделением по лексическим семействам и по конструкциям; не выбирать веса по ранее потраченным S17c NEW24. После заморозки кандидат должен пройти новый независимый prereg EVAL, полный J7/EOS, bpp ≤0,7, CPU ≥90% CB59.

Текущие флаги: `candidate_accepted=false`, `output_gate=0`, `activation_allowed=false`. Нет LIVE, Render, Supabase, APK, main, запуска обычного чата Jessica и изменения оригинальных весов. Система допускает распознавание ролей в контексте всего исходного prompt; строгая онлайн-каузальность не подтверждена из-за глобального prompt-conditioned GT.
