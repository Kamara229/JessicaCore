# CALIBRI 2.0 — S0: первая малая модель, обучение и проверяемый рост

**Статус:** отдельная ветка исследований `research/calibri2-s0-small-first-paid-architecture`; старт с нуля без исходных pretrained весов. Старая CALIBRI2 135M v001 сохранена как технический эталон и не заменяется.

## Цель S0

Запустить действительно меньшую Llama/SmolLM2-совместимую сеть (токенизатор и оригинальный vocab=49152 сохраняем), обучаемую непосредственно в сжатых словарях и индексах. Достичь проверяемого улучшения ответов на **только TRAIN** до добавления следующих операторов. Ноль ответов после 4 шагов случайной 135M не является ошибкой, но означает отсутствие обучения языку.

Порядок проверки **НЕ выбирается по QA**: первые заранее зафиксированные конфигурации в порядке роста — 256×6/FFN768, 320×6/FFN896, 384×6/FFN1024. Каждая архитектура сохраняет RoPE, GQA attention, RMSNorm, SwiGLU, tied embedding/head, тот же оригинальный tokenizer. Выбираем первую конфигурацию, которая после **реальной** сериализации CB59 удовлетворяет ≤0,700 bpp; остальные не обучаем и не проверяем ответами. Это лишь решение о физической ёмкости формата, а не гиперпараметр по отложенным ответам.

Текущий CB59 имеет накладные расходы на row-scales и словари, поэтому совершенно крошечную модель с исходным токенизатором нельзя автоматически считать помещающейся в 0,7 bpp. Если ни один вариант не подходит, эксперимент должен явно FAIL, а не подменять кодек оценкой.

## Основной опыт

1. Создать из `AutoModelForCausalLM.from_config` **случайные**, а не загруженные FP32 веса. Сохранить полный реальный CB59 с реальными байтами, SHA256, количеством матриц и aliases.
2. Проверить numerics своего native C packed inference без декодирования всех весов в FP32 на runtime.
3. Обучить **все** существующие оплаченные FP16 словари на каждом шаге и попробовать 5-bit переиндексацию слоёв по зафиксированному расписанию; опираться только на WikiText TRAIN и противоположные synthetic TRAIN пары.
4. Сохранять учебные контрольные точки **без подбора по QA**, считать правильные законченные ответы (EOS), Yes/No collapse, разнообразие ответов и префиксы.
5. Честно принять/не принять доказательство *обучаемости* по сравнению с первоначальным случайным источником, не объявляя способности FP32. Тесты независимого качества отложены до замораживания модели.
6. После успеха S0 развивать модель по контролируемым шагам роста: preserve layer output / residual identity при добавлении блоков; CPU smoke до нового обучения; regression на фиксированных TRAIN парах до/после. **Это план S1, не считается реализованным на S0.**

## Требования и изоляция

- Физические все данные модели в едином файле ≤0,700 bpp. Не учитывать tokenizer (он общий с FP32 и старой CALIBRI), но считать все нейровеса, индексы, шкалы, центроиды, нормировки, заголовки и метаданные.
- Native C CPU inference ≥90% от CB59 **при идентичной модели на этапе 135M**; отдельная проверка для S0 обязана сравнивать свою скорость с идентичной малой архитектурой, не выдавать прямое сравнение 20M и 135M за справедливое.
- Только `research/calibri2/s0/**`, без main/LIVE Jessica/Render/Supabase/APK. Джессика — исключительно ретранслятор, **тесты она не запускает**. GitHub Actions основного ассистента допустим.
- Никакого обучения на DEV/VALID/QA/TEST и никакого использования FP32 исходных весов как teacher.

Контрольный результат S0 — архив работающего packed pipeline и экспериментальные реальные ответы. Обучение на десятках шагов — начальный smoke, не полноценная предобученная языковая модель.
