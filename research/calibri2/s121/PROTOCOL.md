# CALIBRI S121 — old-gradient nullspace protected paired Green Tunnel

Исследовательская ветка. Никаких изменений LIVE Jessica, Render, Supabase, APK или main. QA/TEST закрыты. Показатели TRAIN НЕ равны качеству на независимых вопросах.

## Мотивация

На исторических 456 TRAIN S101 даёт 353/456 полных+EOS и 387/456 правильных первых токенов. В S115 Green Tunnel активировали только во время prefill: +1 полный ответ, 0 забытых на TRAIN, 0,699828 bpp, ~99,07% исходной скорости. Однако первый независимый S118 на 128 новых вопросах дал 30/128 вместо 31/128 у S101 (и 64 вместо 65 правильных первых токенов). Это отрицательный результат обобщения. Набор S118 уже просмотрен, и его нельзя использовать для обучения, выбора конфигураций или повторных тестов.

S117 показал, что на 340 коэффициентах можно найти ненулевое направление обновления с 0 нарушений 23 старых ограничений в первом порядке; половина градиентных пар конфликтовала. S119 тестирует обновление 8 отдельных wrong-FIRST TRAIN задач с полной физической генерацией; S120 тестирует парные контрфактические исторические TRAIN задачи с GEM-подобными односторонними ограничениями. S121 — отдельный метод с более сильным нулевым воздействием на старые градиенты, а не дополнительная проверка S118.

## Научные ориентиры

Современные методы защищённого обучения исследуют ортогональные представления: Parameter Efficient Gradient Projection (PEGP, IEEE TPAMI, July 2025, DOI 10.1109/TPAMI.2025.3587032), CODE-CL (ICCV 2025), Learning in the Null Space / NESS (PMLR 2026), low-rank projected updates (ACL 2025, GORP). Они мотивируют идею сохранения старого подпространства, но наш код — собственный эксперимент, не воспроизведение их алгоритмов.

## Зафиксированная процедура

1. Исходный настоящий CPU S101 восстанавливается из физического S93 CB61 и неизменного S94/S95/S98, проверяется ровно 353 полных и 387 правильных первых токенов.
2. Выбрать 8 ПОЛНЫХ исторических пар left/right (16 TRAIN) по шести TRAIN семействам с хотя бы одной ошибкой первого токена; обе стороны одной пары должны иметь маршрут S93 из неизменного S95.
3. Получить реальные MPS градиенты для обеих сторон (полный+EOS surrogate и прямой первый токен). Усреднять градиенты пары до одного из 8 направлений, без привилегии одного варианта назначения предметов.
4. Собрать старые градиенты из ВСЕХ 7 правильных ответов, которые повредила S112, 16 дополнительных ранее правильных примеров и ранее правильных обратных сторон выбранных пар. QA/TEST не используется.
5. В FP64 построить SVD старых векторов и ортогональную базу их линейной оболочки. Проецировать новое направление градиентного спуска в ортогональное дополнение этой оболочки; если проекция неопределённа или неортогональна, fail-closed в нуль. Это более строгое условие, чем просто старые потери не увеличатся в первом порядке.
6. Для ненулевого направления провести три заранее заданные физические пробы коэффициентов (максимум 0,015, 0,030, 0,060 на компоненту). Сохранить в одном FP16 safetensors файле только дополнительные 2×10×17 коэффициентов (~680 raw bytes) плюс runtime метаданные о prefill_only; исходные S93 GT3/GT9 и 36M сжатое ядро не изменяются.
7. Выполнить реальный KV-cached S101 S95/S98 CPU декодер по ВСЕМ 456 историческим TRAIN с учётом EOS. Ноль потерь среди 353 ранее правильных полных и всех 387 первых токенов, полный физический bpp ≤0,700000 и CPU отношение ≥0,90. Непрошедшие пробы отклонить; прошедшая остаётся только кандидатом TRAIN, без продакшен-активации.

## Ограничения

Ортогональные градиенты старой дифференцируемой функции потерь гарантируют только нулевое локальное скалярное произведение с защищёнными градиентами. Ни дискретная жадная генерация, ни FP16 квантование, ни работа S98 не обязаны сохранять полные ответы. Реальная CPU проверка остаётся обязательной.

Этот S121 отдельно проверяет гипотезу ортогонального подпространства, чтобы не переобучаться на S118. Для будущего сравнения на новых вопросах нужно заморозить одну модель, заранее зарегистрировать другую независимую выборку и провести проверку один раз, плюс сравнить родные CPU/GPU и свободную генерацию.
