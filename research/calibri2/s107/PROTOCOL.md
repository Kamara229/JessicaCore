# CALIBRI S107 — loss-aware sparse all-layer Green Tunnel ablation (RESEARCH)

## Evidence behind this branch

- S101 frozen reference: 353/456 actual authorized TRAIN full answer + EOS, 387 correct first tokens, 0.699573397602 bpp; no verified new held-out improvement attributed to S103–S107.
- S103 real physical CPU check #42869568472: 456/456 exact zero-gain token parity, 353 full, 387 first, 0.699656519100 bpp, relative S101 CPU ratio 0.9801.
- S104 real MPS learning #42871125920: both bounded gradient steps had nonzero gradients in all ten layer gains; candidate preserved 353/456, lost zero full and first, gained zero; 0.69964354511 bpp, 0.99293 S101 CPU ratio.
- S105 real MPS gradient diagnosis #42873218625: 8 wrong x 12 previously correct TRAIN gradients; **46/96 paired gradient dot products conflict**. The strict all-12 protected halfspace direction projected to zero (`projected_norm_ratio=0`). This shows the current constrained descent objective provides no nonzero *locally certified* improvement direction on those examples. It does NOT prove no gradient-driven improvement exists elsewhere or after non-linear updates.

## Scientific hypothesis

An all-layer shared low-rank residual may be necessary for routing information, yet applying ten simultaneous gain updates can induce opposing skill impacts. Selective tuning of only one/two/three layer boundaries might reduce interference and cause at least one genuinely new complete correct TRAIN response without losing old skills.

S107 performs an **observational, TRAIN-only, full autoregressive CPU ablation** of the already trained (frozen) S104 gain vector. No new training or teacher, no independent QA.

Four configurations are predefined:
1. Best-scored single layer, S104 gain ×2.
2. Second-best single layer, S104 gain ×2.
3. Two best layers, each gain ×2.
4. Three best layers, each gain ×4.

The rankings use only precomputed S105 mean bad-answer gradient and mean protected-answer gradient. The penalty weight (0.75) is an experimental heuristic, not mathematically validated. These diagnostics used *different surrogate loss weights* for wrong and protected examples; we must not interpret their mean slopes as calibrated changes in actual greedy-answer correctness. Only S101 CPU result establishes correctness.

## Exact acceptance guard

Each candidate is physically serialized as S101 original S93 sidecar plus a TEN-float gain vector (zero on all unselected layers), and reloaded from `safetensors`. S93 source CB61, S94 bank, S95 router, S98 copy, and S82 original controllers are SHA-verified and unchanged. The runtime S104 descriptor is counted once in physical bpp. No candidate can exceed 0.7 all-inclusive.

The original 456 authorized TRAIN prompts are regenerated by the unmodified S101 cached CPU decoder and each candidate is regenerated with the exact same frozen S95 route and S98 policy. There is **zero tolerance** for loss of any previously correct 353 full+EOS answers or 387 first tokens. CPU ratio versus original S101 must be ≥0.90 same host. Record gained/forgotten identity hashes, not QA identifiers. A TRAIN improvement is exploratory only, never independent validation or promotion.

Do not try to merge the candidate into LIVE, main, Render, Supabase, APK or run Jessica chat tests. A future independent QA assessment needs fresh pre-registered never-opened questions after a single candidate is frozen.
