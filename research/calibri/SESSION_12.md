# CALIBRI — сессия 12: общий бюджет словарей, точности и поправок

1 ноября 2026. Исследовательская реализация. Исходная версия JessicaCore:
`6057f9c4a1a1a557384b69b8566361c1ae03064a`, PR #133.

## Результат и границы

Исправлен выбор кодека с общим словарём, реализован небольшой точный
распределитель точности страниц и контейнер тернарной страницы с обязательными
FP16-поправками. Проверка механизма выполнена на синтетических весах и входах.
На пяти фиксированных seed расчётный полный контейнер уменьшился на
19,64–20,14% относительно одинакового квантования всех страниц при ограничениях
на ошибку каждого из двух калибровочных распределений. Ошибка на независимых
синтетических входах также снизилась. Это НЕ выигрыш на обученной языковой
модели, НЕ воспроизведение QMoE и НЕ результат для телефона.

В данных специально заданы разные масштабы строк, чтобы проверить механизм
при неоднородной чувствительности. Это благоприятный контрольный пример,
не представительная выборка реальных MoE. Доказательства научной новизны нет.

## 1. Исправлена ошибка учёта общего словаря

В предыдущем `hybrid_codec.encode_hybrid` выбирался DUAL, когда его поток был
короче CL8, без включения стоимости общего LUT в само решение. Поздний подсчёт
LUT в отчёте не исправлял сделанный выбор.

Контрпример: CL8 = 1000 байт, DUAL = 900 байт. Старый выбор экономил 100 байт
потока, но требовал ещё 524288 байт LUT: всего 525188 вместо 1000 байт.
Это обнаруженный крайний случай алгоритма, а не измеренное увеличение
прошлого эксперимента: в сессии 11 обе матрицы уже выбрали CL8.

Для одного общего словаря точное решение без ограничений скорости:

`S = sum(max(0, CL8_i - DUAL_i))`.

Если `S > LUT`, открыть словарь и выбрать DUAL только на выгодных страницах.
Иначе весь пакет остаётся в CL8. Равенство разрешается в пользу CL8.
Обёртки включаются в обе стоимости. Общие масштабы/индексы передаются
отдельной обязательной статьёй расходов. Для нескольких разных словарей
эта простая формула уже не является общим решением.

`encode_hybrid` теперь учитывает LUT целиком для отдельной матрицы.
`encode_hybrid_bundle` выбирает форматы совместно и считает LUT один раз.
Функция возвращает потоки и аудит байтов; это не готовый поставляемый пакет
модели. Поле `external_bytes` должен заполнить вызывающий код, включая все
уровни квантования и внешние метаданные. Python trie занимает дополнительную
оперативную память: 512 КиБ — размер таблицы формата, не RSS этого прототипа.

## 2. Уточнение концепции: возвращать биты туда, где они меняют результат

Для страницы рассматриваются несколько вариантов плотности тернарных весов,
доли FP16-поправок, физического кодека и, при необходимости, высокая точность.
Поправки являются частью выбранной версии весов и применяются обязательно.
Нельзя пропускать их по текущей задаче без отдельной проверки смены модели.

Сборщик минимизирует сумму реальных байтов страниц и единовременных общих
таблиц при отдельных ограничениях на ошибку каждого калибровочного набора.
Редкая группа задач не должна исчезать внутри среднего показателя качества.
Частота маршрутизации сама по себе не определяет чувствительность эксперта.

`precision_frontier.py` — точный эталон для малых задач: хранит недоминируемые
состояния «байты, вектор ошибок, открыт ли словарь». При превышении 20000
состояний останавливается с ошибкой, а не молча выдаёт приближённый оптимум.
Для полной модели нужны иерархическая декомпозиция и масштабируемый решатель.

**Где допустима сумма ошибок.** Для непересекающихся выходных строк одной
линейной матрицы и фиксированных входов сумма квадратов ошибок выходов
аддитивна. В прототипе все страницы используют общий знаменатель — энергию
эталонного выхода соответствующего набора. Через несколько слоёв, ReLU,
нормализацию и маршрутизацию это свойство не переносится. Поэтому сложение
таких оценок по всей сети не может заменить полную проверку качества.

**Поправки.** `residual_page.py` сохраняет CL8-поток, два FP16-уровня на строку,
локальный uint16-индекс и FP16-остаток для каждой поправки, заголовок и CRC32.
Страница ограничена 65535 весами. Ранжирование поправок использует величину
остатка и RMS входной активации; это диагональная эвристика. Кандидат затем
оценивается на полных входных векторах с учётом перекрёстных членов.
CRC обнаруживает случайное повреждение, но не заменяет подпись пакета.

## 3. Эксперимент: проверка распределителя, а не оценка LLM

Данные: синтетическая матрица 96×128 = 12288 весов, шесть страниц по 16 строк.
Масштабы страниц: 0,15; 0,3; 0,6; 1; 2; 4. Два набора входов по 128 векторов:
обычный Gaussian и Gaussian с четырёхкратным масштабом последних 16 каналов.
Независимые отложенные наборы получены после калибровочных; они не участвуют
в подборе вариантов. Синтетическая группа называется «редкой» лишь для
иллюстрации отдельного ограничения; распределение частот запросов не моделируется.

Кандидаты: 88,5% нулей без поправок, тот же режим с 1% или 5% поправок,
75% нулей, 50% нулей, плотный FP16. Нулевые доли навязаны, не получены GPTQ.
Ограничения ошибки равны ошибке режима 75% нулей на каждом наборе отдельно.
Сохранённые FP16-уровни и остатки используются при измерении ошибки.

| Seed | Экономия размера | Ошибка baseline, обычный / второй набор | Ошибка выбранного, обычный / второй набор |
|---|---:|---:|---:|
| 20261101 | 19,8181% | 0,32324 / 0,33388 | 0,27343 / 0,26928 |
| 20261102 | 19,6354% | 0,33133 / 0,32521 | 0,28717 / 0,28790 |
| 20261103 | 20,0906% | 0,33435 / 0,30681 | 0,26822 / 0,26619 |
| 20261104 | 19,9395% | 0,34848 / 0,32175 | 0,27115 / 0,25895 |
| 20261105 | 20,1360% | 0,32206 / 0,32899 | 0,27889 / 0,26331 |

Ошибка в таблице — относительная сумма квадратов ошибки линейного выхода на
отложенных входах; это не perplexity и не доля неправильных ответов.

В первом опыте 2639 → 2116 байт. Физические CR12-страницы сериализованы;
общий индекс контейнера (88 байт) и вариант плотного FP16 посчитаны по
заданному формату, но внешняя модельная упаковка не реализована.
Среди равномерных конфигураций, проходящих заданные калибровочные ограничения,
эталон 75% нулей остаётся самым компактным в этом опыте.

Во всех пяти случаях выбраны пять сильно сжатых страниц и последняя страница
с 50% нулей. **Разреженные поправки не выбраны**: здесь их индексы и FP16-данные
дороже улучшения плотности одной страницы. Выигрыш показывает пользу выбора
точности, но не доказывает пользу нового остаточного представления или словаря.
Общий размер в этом маленьком опыте превышает 1 бит/вес; sub-0.8 не достигнут.

## 4. Сколько поправок вообще помещается в 0,8 бит/вес

Пересчёт опубликованных чисел сессии 11, не новый запуск на её весах:

| Величина для пары 4718592 коэффициентов | Значение |
|---|---:|
| CL8 с уровнями и индексами | 404712 байт = 0,686157 бит/вес |
| DUAL с полным LUT для этой единственной пары | 971283 байт = 1,646734 бит/вес |
| Целевой целочисленный бюджет при 0,8 бит/вес | 471859 байт |
| Остаток сверх старого CL8 | 67147 байт |
| Максимум поправок по 4 байта без новых заголовков | 16786 весов, около 0,356% |

Это оптимистичная верхняя граница: новые страницы, индексы и заголовки
снижают доступный остаток. Нельзя просто добавить 1–5% FP16-поправок и
продолжать считать, что итог ниже 0,8 бит. Маленькие страницы также теряют
часть компрессии из-за заголовков и разрыва статистики. Гранулярность страниц
должна войти в следующий эксперимент как отдельный параметр.
Для всей модели нужно учесть неквантованные части и один общий LUT;
число 0,686157 не является размером полной модели и не доказывает её качество.

## 5. Что является гипотезой CALIBRI

И смешанная точность MoE, и чувствительность блоков уже исследуются:
[MxMoE, ICML 2025](https://proceedings.mlr.press/v267/duanmu25a.html) учитывает
чувствительность, активации экспертов и оборудование, включая вычислительные
ядра; [MoPEQ, ICCVW 2025](https://openaccess.thecvf.com/content/ICCV2025W/BiVision/html/Chitty-Venkata_MoPEQ_Mixture_of_Mixed_Precision_Quantized_Experts_ICCVW_2025_paper.html)
распределяет разрядность по чувствительности экспертов.
Поэтому «дать важным весам больше бит» не заявляется самостоятельным открытием.

Проверяемая гипотеза проекта — совместный выбор размера страниц, общих
словарей, остаточных поправок и физического размещения с точным учётом
байтов и ограничений по разным группам задач Jessica. Опыт Jessica может
давать калибровочные задачи и профили обращений, но не заменять маршрутизатор.
Потенциальный вклад такой комбинации относительно существующих методов пока
не доказан. Графовая перестановка остаётся кандидатом, а не обязательным этапом.

## 6. Воспроизведение QMoE и следующий барьер

Официальный [репозиторий QMoE](https://github.com/IST-DASLab/qmoe) ссылается на
[ISTA-DASLab/switch-base-128_qmoe](https://huggingface.co/ISTA-DASLab/switch-base-128_qmoe).
Карточка подтверждает официальное тернарное квантование и специальный формат.
В этой сессии web-открытие и прямой запрос к API модели дали HTTP 401.
Это ограничение текущего доступа; оно не доказывает, что модель удалена или
требует авторизации для всех пользователей. Веса не были скачаны.

Следующий эксперимент должен получить официальный checkpoint в среде с
доступом и совместимым QMoE/CUDA-окружением, закрепить revision и SHA256,
декодировать одинаковые символы обоими форматами и проверить совпадение.
Нужно сначала воспроизвести формат и качество доступной модели base-128;
это не воспроизводит заявленные 0,8 бит для другого масштаба c-2048.
Для изменения точности дополнительно нужны исходные веса и реальные
калибровочные активации: одного сжатого checkpoint недостаточно для
восстановления утраченной точности. Затем — полная оценка модели на отложенных
данных, а также CPU/GPU/ARM latency, peak RAM, cold/warm I/O и токены/с.

В этой сессии задержка не была измерена и не входит в реализованный
распределитель. Ограничение latency — следующий обязательный этап перед
выбором исполнимой модели. Нельзя считать найденный минимум байтов оптимумом
исполнения. Production Jessica и загрузка весов на телефон не затрагиваются.

## Проверки и воспроизведение

40 задач распределения точности), проверяют отдельный лимит второго набора,
физический roundtrip, ущерб от повреждения, аддитивность по выходным строкам
