# CALIBRI v115 — качество, а не KL или точность исходных коэффициентов

В v114 3 независимых с нуля обученных маленьких LM с настоящим авторегрессионным ответом дали: плотная 7/8, общий структурный оператор 5/8, общий оператор + локальный rank2-корректор 8/8. Но это всего восемь проверочных сочетаний, а в текущем PyTorch-тесте компактный корректор работает значительно медленнее плотного. Scientific gate не прошёл.

Поэтому прежде чем переносить структурную архитектуру на Pythia-14M или SmolLM2-135M, проводим ПОВТОРНОЕ обучение с нуля в 18 вариантах: 2 зафиксированных до нового опыта разбиения из 36 пар цветов/предметов, 3 случайных seed (115/116/117), 3 архитектуры (dense/shared/shared_adapter). На каждый запуск 500 одинаковых шагов. 28 train-пар, 8 не встречавшихся в обучении valid-пар, фиксированные английские запросы с истинным ответом. Ни одна модель не получает логитов или весов другой. Сравниваются полностью сгенерированные токены, правильный фактический ответ, грамматика, EOS, физически сохранённый ПОЛНЫЙ safetensors (включая голову и embedding), парная CPU скорость.

Технические ограничения: весь домен состоит только из 36 простейших контекстных соответствий; обе будущие выборки относятся к тому же изученному в v114 маленькому домену, поэтому не являются независимым open-domain TEST и не доказывают способности вести связный разговор. Исходная цель <=0,7 bpp для настоящих pretrained весов **не измерена** и не выполняется автоматически за счёт сокращения числа параметров новой модели. Маленький прототип лишь проверяет принцип совместных структурных весов с небольшими локальными дополнениями, обучаемых непосредственно под правильность ответов.

Порог до запуска: в каждой репликации плотный контроль должен дать >=90% правильных ответов, компактный не хуже по accuracy и грамматике, CPU >=90% плотного (в том же интерпретаторе). Любая репликация с другим результатом записывается отрицательной. После эксперимента можно делать только новый prospectively зарегистрированный TEST, не подбирать успешные seeds для заявления о стабильности.

Никаких изменений основной ветки, Render, Supabase, APK или живой Jessica. Официальный независимый TEST v89 не открывается.

## Выполненные реальные результаты — Actions #41815441331, технический SUCCESS

На одинаковом CPU выполнены 18 независимых обучений с нуля: два предобъявленных разбиения, три seeds и три архитектуры. Каждый целый checkpoint включая embedding, output и все функции был физически сериализован в safetensors, проверен повторной загрузкой и сохранён. На каждом из шести запусков оценивали 8 новых для конкретного обучения комбинаций.

Положительное: структурные веса с локальной поправкой **повторили фактическую точность Dense на 48 проверках** при 61,9% размера полного чекпойнта, без имитации исходных логитов, весов, KL или NLL. Это более устойчивый сигнал, чем 8/8 единственного удачного seed v114, но всё ещё синтетический узкий домен; результаты отдельных seeds/разбиений не являются независимыми реальными пользовательскими задачами.

Отрицательное: качество не стабильно по всем отдельным репликациям: shared+adapter **четыре раза равна dense, один раз лучше на один ответ и один раз хуже на один ответ**; итог 45/48 и 45/48. Shared часто слабее. **CPU speed модели с адаптером ~0,60 плотного** (медианы 371,7 против 621,1); установленный нижний предел 90% не выполнен НИ В ОДНОЙ из шести сравнительных репликаций. Следовательно, **нет научного или продуктового PASS**, нет основания сразу переносить этот Python runtime на большие модели.

Гипотеза следующего практического шага: убрать чрезмерные Python dispatch и многократные мелкие BLAS-вызовы компактного U(Vx) через специализированный CPU kernel/fused вызов, не реконструируя исходную независимую матрицу W. Сначала проверить численное равенство output/token IDs и бенчмарк на тех же frozen шести checkpoint source. Затем расширять задачу с 36 простых сочетаний до многоконтекстной инструкции/перефразирования, а также языковой тест на настоящих pretrained 14M/135M только после достаточного функционального качества. Никаких утверждений <=0,7 bpp для pretrained checkpoint.
