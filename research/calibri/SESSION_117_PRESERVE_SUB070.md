# CALIBRI Pro Max v117 — возвращаем единую линию <=0.7 bpp

## Решение 2026-11-04: никакой замены CB59 на v114–v116

Пользователь справедливо потребовал: не сбрасывать достигнутые <=0.7 bpp, а НАСЛАИВАТЬ новые научные идеи на существующий физически упакованный прямой кодек.

Факты:
* SmolLM2-135M-Instruct, pinned revision 12fd25f77366fa6b3b4b768ec3050bf629380bac, уникальных исходных параметров 134 515 008.
* Сохранён ПОЛНЫЙ физический CB59 native archive **11 229 303 байта, 0.667839 bpp**; SHA256 **50eac24ba7d7a452c495f8adced2cdef3f9cc44e024217fc21d8f2cebb87413c**. Он технически полностью читается напрямую C/GEMV без плотных 2D источников, но его настоящее качество речи ПРОВАЛЕНО. Это нельзя скрывать.
* Полный предел при <=0.700 bpp: **11 770 063 байта**, запас перед дополнительными данными **540 760 байт**.
* Игрушечные v114–v116 создали отдельную, с нуля обученную структурную архитектуру, физический размер 23 356 байт против 37 724 плотного 8951-параметрного аналога; 20.87 эффективных бит на параметр первоначальной toy-архитектуры — НЕ замена реальному 0.667839, не прямой шаг назад до 20.87.
* v116 демонстрировала ПРИМЕНИМОСТЬ block-local generated operator к скорости и сохранению ответов на ТОЛЬКО искусственной задаче. Новый технический мотив использовать как коррекцию/дополнение к существующему нативному CB59, а не менять denominator или выбирать масштабированные 20.87 bpp из toy.

## Первое строго ограниченное объединение

v117 хранит **оригинальный полный CB59 byte-for-byte**, добавляет физически оплаченный rank-2 factor U/V для каждого из 30 attention o_proj и 30 MLP down_proj: итого 60 групп, **391 680 байт дополнительных FP16 факторов**. Полный архив включает исходные 11 229 303 байта, все 391 680 байт факторов, реальную карту ролей и offsets, CRC32 и SHA256; запрещается нарушать предел 11 770 063. Нативный runtime применяет PackedLinear из неизменной CB59 и вычисляет небольшую функциональную коррекцию U(Vx) без создания dense оригинальных 2D весов.

**ВНИМАНИЕ:** текущие новые факторы заполнены нулями, только чтобы доказать интеграцию и корректный физический бюджет. Это **не означает улучшение качества**; эксперимент обязан показать ровно те же плохие ответы. Базовая кодовая книга оригинальных весов остаётся неизменной; после обучения факторов на фактических полезных ответах должен измениться сам текст и точность. Пока реальное обучение новых факторов НЕ проведено. Их нельзя считать моделью, прошедшей PASS, даже если технические тесты SUCCESS.

## Следующий алгоритм (после успешной проверки физического формата)

1. Заморозить исходную CB59 и оптимизировать 60 rank-2 структурных корректоров по TRAIN только для фактического **правильного ответа**, связности, следования инструкции, без KL-имитации FP32.
2. Учить совместно последовательные блоки и пробовать другие назначения 540 760 байт (tied embedding/head, attention, MLP) за ПОЛНЫЙ одинаковый бюджет. Исправление только MLP+o_proj может оказаться бесполезным, поскольку v111 показала распределённую ошибку E/B/H.
3. Контроли: неизменённая CB59, однократная отдельная коррекция, joint correction при той же физической цене, полноценная исходная INT6 только как независимый качественный контроль. Не обращаться к v89 независимому TEST до фиксации веса-кандидата.
4. VALID: 100+ размеченных разных задач по математике, фактам и инструкциям, дополнительно связная свободная речь и контроль повтора/обрыва. Оценивать фактический правильный ответ относительно задачи, а не соответствие логитам INT6. Качество <= исходной осмысленной INT6 по согласованной рубрике. Физически общий источник **<=0.7 bpp**, CPU >=0.9 CB59, никакие большие неучтённые буферы.
5. Если фактические корректоры не вернут качество, не объявлять успех по storage; перераспределить поток и менять сами операторы/структуру, оставаясь в том же 0.7-файле. Не обещать, что игрушечные 20.87 bpp гарантированно сожмутся 30x.

Код через мелкие facades: v117/protocol.py, archive.py, runtime.py, experiment.py, unit tests, отдельный CPU workflow. Без изменений Jessica LIVE/main/Render/Supabase/APK. Независимый v89 TEST не трогать.

## Настоящий 135M эксперимент — GitHub Actions #41818373409, SUCCESS (2026-11-04)

**Проверка выполнена на реальной полной SmolLM2-135M-Instruct, а не toy.** В Actions исходный 135M CB59 был пересоздан из неизменной ревизии обученных весов и прошёл точный frozen SHA. Полный физический архив CB117 сохранён и проверен: **11 624 191 байт = 0,6913245546548977 bpp при исходных 134 515 008 параметрах**. Первоначальные CB59 **11 229 303 байта, SHA неизменен**. Новые платные 394 888 байт включают 391 680 байт FP16 U/V для 60 role-specific операторов + 3208 байт заголовка, карты и проверок целостности. От потолка 11 770 063 байта осталось **145 872 байта**. Финальный целый архив SHA256: 041b16ef94492bcdc385d1873dcdbc5016b200a5b7922692354df5e307f86a37.

Реальный C-native PackedLinear runtime на 60 операторах обёрнут структурным адаптером, не разворачивая FP32 матрицы исходных весов. Три настоящие проверки в оригинальном чат-шаблоне SmolLM2 (столица Германии, 12+19, зачем деревьям солнечный свет) дали **3/3 точное совпадение идентификаторов сгенерированных токенов** между CB59 и CB59 + НУЛЕВЫЕ корректоры. Сам текст остался непригодным: «compon speci speci ...». Это ожидаемый, явно записанный **научный FAIL качества**, а НЕ восстановление языка. Новые структурные факторы пока НЕ обучены, не было теста нового ненулевого обученного оператора; техничность сборки не считать функциональным PASS.
