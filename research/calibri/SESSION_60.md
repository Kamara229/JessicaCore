## Single predeclared algorithm change

**CB60**: Keep exactly the same source-only deterministic integer-nearest 32-centroid (K32), FP16 8D vector dictionary and 5-bit ID per contiguous 8 original weights, FP16 RMS source row scales and lossless FP32 1D trained vectors, tied alias metadata, full CRC/SHA, and full source-name/shape coverage. **Replace a single 32×8 dictionary for EACH matrix** by **one private 32×8 dictionary for EACH contiguous block of 256 output rows of each original matrix**. Shorter matrices with <=256 rows remain single dictionary; a 576-row projection gets three dictionaries; source tied embedding ~49k rows gets many. All dictionary copies **really occupy bytes** inside a new entire physical CB60 checkpoint. No sidecar, no hidden teacher model. Total actual entire archive must fit `floor(0.700 × 134515008 / 8)` bytes, i.e. <=0.70 bpw INCLUDING all stored codebooks, row scales, exact 1D vectors, aliases, metadata, CRC and SHA.

Kmeans: 5 deterministic iterations per row-tile dictionary, at most 4096 evenly spaced normalized source-only vectors per tile, FP16-snapshotted centroids and 1/128-grid deterministic int32/int64 nearest assignments, same as v59. Never sample TASK/TRAIN/TEST text to fit. Store tile_count×32×8 FP16 centroid codebooks in physically verifiable array; per-tensor manifest records tile_rows=256 and all segments. Any shape/overhead discrepancy fails integrity. Source-only weighted global relative RMSE and individual highest-error tensors recorded for both v59 baseline and CB60 from **same exact pretrained source in a single encode run**, so comparison is apples to apples and cannot be gamed by changing source weights.

**Native direct inference must remain functional:** new C `tiled_kernel_v60.c` chooses the correct codebook per output-row tile, recomputes activation×32-centroid LUT per row tile and streams 5-bit packed code IDs directly; embedding only decodes requested row, tied LM head uses same shared compressed handle. No reconstructed full trained 2D FP32 matrix during packed runtime. Compare the compiled C kernel against explicit dense materialization **only in local synthetic smoke tests**, including 2+ codebook row tiles, not in actual inference. Whole `SmolLM2` from_config full forward on fixed fresh prompt 8 tokens and actual next autoregressive KV step must have finite logits; no original teacher weights loaded in that packed process. Baseline v59 must also be encoded and executed from its own real physical file for matched comparisons, never copied from old measurements.
