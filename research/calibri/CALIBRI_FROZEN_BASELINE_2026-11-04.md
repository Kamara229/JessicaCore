# CALIBRI — заморозка достигнутой базы перед улучшением качества (4 ноября 2026)

## Остановка расширения экспериментов

Цель остаётся **максимально сжать оригинальные обученные веса с сохранением исходной полезности и скорости**. Не выбирать новую модель потому, что она превосходит уже испорченную квантованием CB59; сохранение функциональности сверять с исходным FP32 **только по правильным ответам и качеству реальной генерации**, никогда не по совпадению распределений. Исторические KL/NLL результаты не удаляются, но **не входят в оптимизацию или критерии выбора**.

**Текущее решение:** не менять физические архивы, не обучать новый оператор и не переходить к очередной версии компрессора. Разрешено только завершить уже запущенную проверку v94 и проанализировать, какой ущерб качеству возникает при удержании достигнутых показателей размера и скорости.

Важное уточнение терминологии: **не менее достигнутой степени сжатия** означает **не более 0.700 бит на исходный параметр**. Чем меньше bits/parameter, тем компактнее архив. Сохранение именно 0.678805 или 0.667839 предпочтительнее расходования допустимого резерва. У CB88 остаток лимита всего 356,380 байт, и он не предназначен для автоматического расходования.

### Историческая измеренная скорость

Фиксированный отчёт v89 GitHub Actions #41586756881 на одной CPU-конфигурации, четыре KV-cache greedy prompt:
- CB59: 22.7315074869 токен/с.
- CB88: 22.4344903032 токен/с, то есть 98.693% скорости CB59.

**Сохраняем текущую фактически достигнутую скорость, а не ориентируемся только на ранее допустимую потерю до 10%.** Новая версия должна демонстрировать отсутствие существенной потери относительно **выбранного уже достигнутого компактного родителя** на той же конфигурации и репрезентативной новой TRAIN-only нагрузке. Исторические четыре prompt — ориентир, а не статистически надёжная гарантия, и тем более не текущая скорость работающей Jessica. Результаты замороженного v89 независимого TEST нельзя использовать для подбора новых операторов; прежние численные показатели хранятся как архивное доказательство.

## Жёсткие инварианты дальнейшей работы

1. Не изменять оригинальные архивы CB59/CB88/v92; только отдельные исследовательские копии, строго с SHA256.
2. Полный архив модели со всеми метаданными, корректорами и проверками целостности **не превышает 0.700 bits/parameter**; при одинаковом качестве приоритет меньшему архиву. Не тратить уже выигранные биты по умолчанию.
3. Сохранить блочный доступ, нативный CPU runtime, исходное ABI и фактическую скорость; полный замер до/после на одинаковом оборудовании важнее микробенчмарка.
4. Главная метрика качества — **правильные реальные ответы** против исходной FP32, плюс содержательность, корректность и связное разнообразие генерации; не «любой рост разнообразия».
5. Иметь стабильные TRAIN и отдельно TRAIN_VALID; **не** подбирать гиперпараметры на уже открытом v89 официальном TEST.
6. Качество улучшать **поверх фиксированной компактной базы**, постепенно, через фасады: диагностика проблемного блока → бюджетно-нейтральная перепись целого оператора → проверка сохранения результата → принятие либо откат.
7. При невозможности улучшения без ухудшения размера/скорости/общей функциональности сохранять baseline и документировать отрицательный эксперимент. Сначала альтернативные физические кодировки с тем же бюджетом; корректор с лишними битами — только отдельно обоснованное исключение.
8. Ни одна исследовательская ветка не меняет Live Jessica, main, Render, Supabase или APK. Никакой автоматической установки без отдельного разрешения.

## Порядок следующего решения

Сначала завершить **уже запущенный v94 как диагностический контроль**: увидеть FP32, CB59 и v92 на 128 BoolQ + 64 SciQ, decoded greedy и полной CPU скорости; без изменений исходных весов. Отметить все регрессы и неопределённость. **До этого не запускать новый подход сжатия/переработки операторов.**

Источник фиксированной машиночитаемой базы: CALIBRI_FROZEN_BASELINE_2026-11-04.json. Это документ и reference lock, **не гарантия PASS по качеству**; v89 научно не прошёл BoolQ и генерацию, и это отрицательное достижение сохраняется честно.
