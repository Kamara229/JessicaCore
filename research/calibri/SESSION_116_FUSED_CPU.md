# CALIBRI v116 — более быстрый функционально эквивалентный CPU-оператор

Сведения на входе: v115 фактически сохранила 18 новых моделей в полном физическом safetensors. Структурные операторы с адаптером сохранили корректность исходной плотной tiny-модели на 45/48 проверках, занимая 61,9% её физического файла, но наивная PyTorch-реализация U(Vx) работала с ~60% плотной CPU-скорости. Оригинальные логиты/веса не имитируются.

Идея v116: источник по-прежнему содержит только U, V, индивидуальные масштабы, смещения и rank-2 исправления. После загрузки такого source реконструируется НОВАЯ вычислительная матрица W_generated=(U@V)*gain + U2@V2 исключительно для выбранного блока. Это не восстановление исходных независимых FP32 весов. В работе вычисляется один F.linear на роль вместо цепочки маленьких matmul; временные generated W buffers в RAM замеряются и оплачиваются отдельно. На toy-модели все три блока могут находиться в RAM; для крупной модели нужна ограниченная буферная очередь из одного-двух блоков и выгрузка остальных.

Старые модели **не переобучать**. Взять ровно артефакт #13314631058 завершённого v115 Actions #41815441331, сверить SHA всего JSON и всех 18 моделей. Для всех 6 пар плотный/compact сделать замеры исходного compact и нового generated_fused на том же CPU с чередованием порядка. Проверить численное равенство логитов до 5e-5 и **точное тождество всех 36 ответов** на каждом frozen compact checkpoint. Произвести 216 целых сравнений ответов без подбора по VALID. Предобъявленный порог скорости >=90% плотной; результат PASS или FAIL отчитывать одинаково. Сохранять весь новый список байт hot buffers и физические старые checkpoint sizes.

Это **не производственный native decoder** для 135M и не свидетельство полного <=0,7 bpp: распакованные новые матрицы увеличивают горячую память. Техническое улучшение даёт лишь новую гипотезу о block cache и native streaming. Никаких изменений main, Render, Supabase, APK или Jessica Live. Официальный TEST v89 не открывать.

## Результат настоящего CPU GitHub Actions #41816191294 (SUCCESS)

Источник: ровно те же замороженные 18 физических safetensors v115 из artifact #13314631058. JSON SHA256 и все восемнадцать индивидуальных source SHA проверены. **Ни одного нового обучения, ни одной подмены исходных весов**. Все шесть compact source+rank2 checkpoint по 23 356 байт против полной dense-базы 37 724 байта (61,9%). Для ускорения из этих компактных параметров на уровне 3 локальных блоков были вычислены и временно размещены в RAM синтезированные матрицы. Суммарный РАСХОД дополнительного горячего пространства для шести generated W: **24 576 байт**, который обязан учитываться отдельно от компактного файла.

На всех шести frozen моделях проверено фактическое совпадение ВСЕХ 36 самостоятельных авторегрессионных ответов модели до/после преобразования, итого 216/216 последовательностей токенов совпадают побитно. Максимальное расхождение логита 5,25e-6. Истинное качество по ответам сохранено, не дистиллируется и не измеряется через KL учителя.

| CPU режим | Относительная скорость против Dense |
|---|---:|
| Исходный unfused U(Vx), медиана 6 повторений | 0,6038 |
| **Generated-block fused GEMV, медиана** | **1,0643** |
| Худшая из шести парная скорость Generated | **1,0219** |

Предварительно заданная нижняя граница CPU >=0,9 от плотного референса выполнена **6 из 6**. Это конкретное практическое достижение: новые веса не обязаны повторять старые, а их вычислительная форма может быть синтезирована из небольшого числа структурных параметров на лету (в начале инференса) с ускорением на маленьком моделе. Однако в данном опыте мы кэшировали *все три маленьких блока*, а не тестировали строгий bounded-memory streaming в большой модели. Глобальный RAM/cache бюджет не равен компактному файлу и должен оплачиваться отдельно. Здесь эталон скорости Dense tiny, НЕ CB59 на 135M. Это не доказывает общий порог 0,7 bpp/качества настоящего LLM. Нельзя считать v116 прикладным CALIBRI PASS.
