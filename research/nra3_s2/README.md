# NRA2 3.0 S2 — actual CB59 5-bit C CPU operations + Green Tunnel

**RESEARCH-ONLY / zero-gate / untrained, NEVER merged into LIVE.**

This step changes the S1 compressed physical source from a cold-FP32 reference into a genuinely executable *native 5-bit operator path*. The original CALIBRI `research/calibri/direct_kernel_v59.c` is compiled to a CPU shared library and used to execute **every 2D NRA3 weight** (43 unique matrices in the 6,106,154-parameter default configuration), including grammar/semantic self-attention QKV/out projections, FFN, UPOS/morphology/role heads, relation query/key/value, two GRU cell matrices, and readout. Index codes remain packed and codebooks/scales small FP32 metadata; matrices are **never reconstructed into persistent dense 2D weights** during native inference. 1D raw FP32 norm/bias weights are paid by the same physical CB59 file.

The native `NRA3NativePackedCPU` shares the same causal `NRA3Features` contract as S0. Test compares every feature against a **dense reconstructed reference of the SAME quantized weights**, with CPU tests on tiny and full 6M models, for correctness of the packed implementation—not against original FP32 language accuracy. Some numeric roundoff is expected. The new native area is permitted behind the strict *read-only* layer-8 port and existing frozen S87 Green Tunnel plus optional S103 all-layer bridge. Route-scoped toy decoder outputs must be **exactly identical** with `output_gate=0`.

The original 43M CALIBRI weights, cached generation path, Green Tunnel and LIVE behavior are untouched. No training of Russian text or new generalization evidence occurs in S2. No replays of consumed independent EVALs and no claim/activation of reserved sixth EVAL128 in S3CI/#702. No real 616 protected J7 or matched full-model CB59 CPU speed measurement is claimed. The shared native C kernel is an unoptimized CPU reference and may fail the >=90% token-speed gate.

Next work: (a) train source codebooks and discrete index candidates **using permitted TRAIN only**, with exact physical CB59 serialization between optimizer stages; (b) prove performance under same CPU architecture/Green Tunnel+cache; (c) train Russian grammar/semantic/relational heads and establish *new full-answer+EOS generalization* without accessing prior sealed EVAL data. Only after every gate passes may a separately reviewed read/write integration be proposed; `candidate_accepted=false`.
